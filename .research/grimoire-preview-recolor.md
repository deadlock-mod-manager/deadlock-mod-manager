## Prioritized findings

### 1. Reuse the material/data contract before considering the complete viewer

The reusable boundary is **GLB + `material.extras.morphic` + optional physics/attachment/particle sidecars**. This is not a browser renderer for raw VMDL/VPCF. The native helper resolves and exports game assets; Three.js renders derived assets. [`resolveMorphicTextures`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/src/lib/source2NprMaterial.ts#L410) resolves extra texture indices while the glTF parser is live and applies guarded legacy tint handling. [`parseGltfPreview` / `loadGltfPreview`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/src/lib/loadGltfPreview.ts#L33) are relatively small entry points.

Best rendering references:

- [`buildDeadlockMaterial`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/src/lib/deadlockMaterial.ts#L226): owned material clone; shared NPR GLSL; tint/rim/self-illumination, packed masks, sheen/glass/translucency decisions; explicit disposal of the wrapper, base clone and owned textures. It imports substantial logic/GLSL from `source2NprMaterial.ts`, plus `dynamicScalar.ts` and `source2NprLighting.ts`; it is not an isolated copy-paste function.
- [`resolveSource2DrawState` / `applySource2DrawState`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/src/lib/source2Preview/drawState.ts#L40) and [`compileSource2DrawState`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/src/lib/source2Preview/compileScene.ts#L25): pure blend/depth/cull planning plus reversible scene application. Particularly useful for additive overlay shells and translucent depth-writing distinctions.
- [`applySource2ColorCorrection`, `source2TintMatrix`, `source2TintPlan`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/src/lib/source2ColorCorrection.ts#L12): channel-specific reflectivity pivots, linear unclamped correction, tint modes, and schema/value checks preventing double sRGB conversion. The code prioritizes compiled `texture_reflectivity` when supplied and otherwise uses an approximate decoded-albedo mean. Current fallback sampling is **256 pixels on the longest edge**, despite an older doc saying 2048. [`albedoReflectivity`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/src/lib/source2NprMaterial.ts#L527), [sampling code](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/src/lib/source2ColorCorrection.ts#L71).

**Integration judgment:** adapt these algorithms and their metadata contract to DMM's asset output. Preserve provenance and schema guards. Copying `HeroPoseViewer.tsx` wholesale would bring application state, IPC URLs, capture, backgrounds, physics and editor dependencies with it. Lighting coefficients remain a preview approximation; the code does not establish Source 2 renderer parity. [Architecture](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/docs/viewer-architecture.md), [color-pipeline attribution to ValveResourceFormat](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/docs/viewer-color-pipeline.md).

### 2. The skin-edit model and export guards are useful independently of Electron

Edits address **authored material groups**, not arbitrary vertex selections. Shared materials change every matching mesh. [`SkinPartEdit` / `SkinEditInfo`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/src/types/skinEditor.ts) carry visibility, tint, HSV adjustment, pattern and roughness/metalness. [`skinEditExportSchema`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/src/lib/skinEditSchema.ts#L29) bounds inputs; [`partsFromDrawCalls`, `getSkinEditInfo`, `validateSkinEdits`, `buildSkinEditVpk`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/electron/main/services/skinEditor.ts#L20) inspect capabilities, reject stale sources/duplicate or unknown materials/all-hidden models, and build separate hidden/pattern/tint/finish layers before merging.

Small renderer-side references: [`applySkinPartEdits`, `highlightSkinPart`, `dominantSkinColor`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/src/lib/skinPartPreview.ts#L21), [`adjustSkinPixels`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/src/lib/skinColorAdjustments.ts#L13), and [`editForMaterial`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/src/lib/skinParts.ts#L21). Skin HSV uses a **relative hue rotation** and saturation/brightness multipliers while retaining alpha. Material tint is a separate operation. Multiplicative tint/brightness cannot turn black into white.

[`saveSkinEdits`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/electron/main/services/saveSkinEdits.ts#L43) is an architectural reference: build in temp, inspect safety, revalidate sources inside a serialized mutation, enable dependencies, place the overlay ahead of its sources, replace matching previous overlays, and return renamed source identities. [`resolveSkinEditSources` / `skinOverlayLoadOrder`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/electron/main/services/skinOverlay.ts) prevent editing overlays recursively. Adapt these invariants through DMM's existing file owner; Grimoire's installation services are tightly coupled to its own mod metadata/load-order system.

**Limit:** the stale-source fingerprint is SHA256 of model entry + source **stat-derived** fingerprint + base-directory-VPK size/mtime, not a cryptographic digest of all source/archive bytes. Source stats are MD5-combined/truncated for preview keys. Overlay dependency metadata separately records canonical source SHA256 identities. Do not describe cache fingerprints as full content integrity verification. [Fingerprint code](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/electron/main/services/heroPoseModels.ts#L723).

### 4. Ability recolor is a native recipe pipeline, distinct from skin HSV editing

[`heroColors.ts`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/electron/main/services/heroColors.ts#L212) calls `recolor-hero`, `prism` or `trippy-vfx`, verifies output, caches bakes, and combines per-hero results into a managed ability-colors VPK. `previewHeroColor` invokes the helper's representative-texture PNG mode; it is a real transformed swatch, not complete ability simulation. [`abilityColorPreview.ts`](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/src/lib/abilityColorPreview.ts) has reusable shortest-hue-arc gradient interpolation/spec parsing, but CSS brightness is explicitly approximate.

The actual compiler lives in **vpkmerge**, not Grimoire: pinned v0.26.0 resolves to [`59266e928478cc33410149ba860a566aeba87a71`](https://github.com/Slush97/vpkmerge/commit/59266e928478cc33410149ba860a566aeba87a71), released October 24. [`recipe_for` / `recolor_hero_to_addon`](https://github.com/Slush97/vpkmerge/blob/59266e928478cc33410149ba860a566aeba87a71/vpkmerge-core/src/hero_recolor.rs#L1856) combine particle RGB scalars, color-bearing textures, material constants and vertex colors. Ability recolor sets an **absolute hue**, scales existing saturation/value, and preserves structural variation. This differs from skin hue rotation.

Reuse the **patch-without-losing-resource-types** principle: native code calls `morphic::patch_kv3_resource_scalars`; generic decode/edit/re-encode can destroy KV3 framing/resource flags. Shared resources are isolated as hero-local copies with repointed references rather than recolored globally. Missing required recipe assets fail; unpatchable particles/materials can instead be skipped and left vanilla with report counters. Those partial results should remain visible in an integration. Recipes are curated tables, not universal automatic asset discovery. [Mechanism and isolation contract](https://github.com/Slush97/vpkmerge/blob/59266e928478cc33410149ba860a566aeba87a71/vpkmerge-core/src/hero_recolor.rs#L1), [bake behavior](https://github.com/Slush97/vpkmerge/blob/59266e928478cc33410149ba860a566aeba87a71/vpkmerge-core/src/hero_recolor.rs#L1880).

Two integration limits follow from current code: the app's `runVpkmerge` returns no report on success, and `verifyVpkOutput` checks file size/magic rather than full resource validity. Also, ability-color cache names include recipe version and color settings but **no game package identity**, so an unchanged pin/version can reuse a pre-update bake. [Process/output checks](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/electron/main/services/modMerger.ts#L151), [cache naming and reuse](https://github.com/Slush97/grimoire/blob/1722ba9ec337b8de9e755645710c2e3fbc506e4c/electron/main/services/heroColors.ts#L174). These are code-derived limits, not reproduced failures.
