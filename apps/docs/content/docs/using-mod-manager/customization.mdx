# Customization

## Hero Skins

![Hero Skins with an empty library and the default Abrams 3D preview](/assets/v2-hero-skins.png)

1. Download a hero skin from **Mods Store**.
2. Open **Hero Skins** and find the hero using search.
3. Select a downloaded skin, or choose **Default** for the vanilla appearance.
4. If the skin has variants, select the ones you want active.
5. Restart Deadlock if it is running to see the change.

Sounds and other mods appear separately from skins so you can toggle them independently. If a mod is missing or listed under the wrong hero, use **Assign Mod** or set its hero override in Mods Library. Choose **Remove from hero** to remove the hero assignment and keep the mod in your library. To remove the mod itself, delete it from the library.

**Settings → Hero Skins** can group sounds and weapon skins by hero or allow several skins per hero. Use multiple skins only when they change complementary parts; two full skins can conflict.

The optional **3D preview** shows supported hero models. You can turn it off under **Settings → Application → Appearance**. A skin can work in-game even if its preview fails to decode.

## Mod Foundry

![Foundry editor with stock Abrams loaded, asset list, and Paint, Cards, and Sounds tabs](/assets/v2-foundry-editor.png)

Foundry edits hero skins and exports the result as a VPK. Enable **Mod Foundry** under **Settings → Experimental** if its navigation entry is hidden.

![Foundry import dialog with Default, My Mods, and Local file tabs](/assets/v2-foundry-import.png)

1. Open **Mod Foundry** and choose **Import skin**.
2. Choose a default skin, a downloaded hero skin from the **My Mods** tab, or a **Local file** VPK. Map mods are not accepted as skin inputs.
3. Recolor the body and weapon, change cards, or swap sounds using the editor panels.
4. Choose **Export** and select a destination.

| Destination              | Result                                                                           |
| ------------------------ | -------------------------------------------------------------------------------- |
| Save to a file           | Writes a VPK to a location you choose.                                           |
| Add as a new mod         | Adds a local mod to your library for installation.                               |
| Replace the original mod | Overwrites the source mod VPK and keeps the original beside it as a `.bak` file. |

A default skin imported from the base game has no original mod to replace. Install and enable exported mods before launching; restart Deadlock after replacing an active skin.

You can disable **Load the 3D preview** during import if a model is slow or fails to decode. Painting, cards, and sound editing remain available.

## DeadlockForge installs

[DeadlockForge](https://deadlockforge.net) is a separate community workshop. To send a mod from the website to the manager:

1. Keep Deadlock Mod Manager open.
2. Use Settings search to find **1-click installs from DeadlockForge** and enable it.
3. Use the website's install action and review the manager's confirmation.
4. Accept the import, then enable the new mod in Mods Library when you are ready to use it.

Imported mods stay disabled until you enable them. The manager asks before installing each mod, and you can turn the integration off in Settings.

## Crosshairs

![Crosshair editor with preview, import, apply, and publish controls](/assets/v2-crosshair-editor.png)

Open **Crosshairs** to browse community crosshairs or create a configuration in the editor.

Search or filter the community library to find a crosshair. In the editor, use **Import** to load a configuration, adjust it using the preview, then choose **Apply**. To **Publish** your design, sign in and fill in its name, description, tags, and hero choices. Publishing requires an internet connection.

The manager writes crosshair settings to the managed section of `autoexec.cfg`. Enable the **Autoexec Config** launch option in game settings so it runs when Deadlock launches.

## Autoexec Config

![Autoexec command library and category filters](/assets/v2-autoexec.png)

![Current Autoexec Config editor below the command library](/assets/v2-autoexec-editor.png)

Open **Autoexec Config** from the sidebar or Settings to edit startup console commands.

1. Browse or search the **Command Library** and choose **Add** for a command you want.
2. Review its value in **Current Autoexec Config**, or enter your own commands.
3. Save the config and enable the **Autoexec Config** launch option.
4. Restart Deadlock for the commands to take effect.

<Callout type='warning' title='Keep managed sections intact'>
  Sections marked DO NOT EDIT are managed by the app and restored when saving.
  Keep the config nonempty when the autoexec launch option is enabled. The
  command library comes from the community; commands can change or stop working
  after game updates.
</Callout>

## Performance configs

Performance configs are community `gameinfo.gi` tunings that trade visual detail for frame rate. Enable **Performance Configs** under **Settings → Experimental**, then open **Performance** from the sidebar.

1. Pick a config on the **Configs** tab. Curated presets, configs published on GameBanana and your own imports share one list, and the **Looks best ⟷ Runs fastest** scale above it filters them by how much they cut.
2. Choose **Details** to see what a config changes, the in-game video settings its author recommends, and anything that won't be applied.
3. Choose **Apply**, then restart Deadlock if it is running. The game reads these settings at startup.

The manager edits `gameinfo.gi` in place next to your mods instead of replacing the file, and marks every line it changes so **Turn off** can put the original values back. A game update or **Reset to Vanilla** replaces the file; the manager writes your config again when it starts, when you switch back to its window, and before every launch from it, including vanilla launches. It waits while Deadlock is running, so starting Deadlock from Steam while the manager is closed leaves the config out until the manager next runs.

What gets written:

- Settings that Valve's convar list marks as not read from `gameinfo.gi`, or that aren't in that list at all, are left out and listed in the config's details. The list comes from the newest game build the catalog knows.
- Edits outside the ConVars block (SceneSystem, RenderSystem and other engine sections) are left out unless you choose **Include** for that config. Deadlock's matchmaking error lists Engine2, MaterialSystem2, NetworkSystem, Particles, RenderSystem, SceneSystem and WorldRenderer as `gameinfo.gi` sections where it doesn't support changes.
- Camera and visibility settings, such as field of view or outlines, follow the config's author. You can turn each one off.
- SearchPaths and `video.txt` are never changed.

Use **Settings editor** to change any value the config sets, turn individual settings off, or add another setting. Each setting shows the config's value next to the game's default.

**Import config** accepts a pasted `gameinfo.gi`, a ConVars block, autoexec lines, a share code, a file or archive, a GameBanana mod link, or your current `gameinfo.gi`. The review shows what will apply and what won't before anything is written. When a mod you download includes a performance config, the manager asks whether to import it; it never copies a mod's `gameinfo.gi` over yours. **Share** gives a share code and a ConVars snippet for the config you have applied.

<Callout type='info' title='If Deadlock crashes after a change'>
  When Deadlock closes abnormally within a few minutes of starting, the manager
  lists what changed since your last normal session, such as a new performance
  config or new mods, with a way to undo each one. Turn this off under
  **Settings → Game → Check for crashes after launch**.
</Callout>

## Discord game presence

![Discord game presence templates and preview](/assets/v2-discord-presence.png)

Open **Settings → Discord** to enable Discord Game Presence and customize how your live Deadlock status appears on Discord. It can display hero, match mode, party size, and other game information.

Enable **Console Debug Log** in Launch Options so the manager can read game status. Keep Discord and the manager running. Edit the top-line and bottom-line templates using placeholders, set per-hero overrides if needed, and check the preview before saving. Empty template fields fall back to defaults.

## Plugins and themes

Open **Settings → Themes** for predefined themes, accent controls, and the custom theme builder with a live preview. Save a custom theme as a predefined entry to activate or edit it later. See [Themes](/plugins/themes) and [Plugins](/plugins) for background and Flashbang plugin instructions.
