# AI 贡献政策

> **最后更新：** 2026 年 2 月

## 我们的立场

Deadlock Mod Manager 借助 AI 辅助构建，我们对此毫不避讳。我们的 [Cursor 配置](https://github.com/deadlock-mod-manager/deadlock-mod-manager/tree/main/.cursor) 包含在仓库中，因为我们相信 AI 工具是现代开发者工具库中合法且强大的一部分。

话虽如此，AI 工具会放大使用者的技能。优秀的开发者借助 AI 会变得更快。而不理解自己提交内容的开发者，无论代码是如何生成的，都会成为维护者的负担。

**这不是一条反 AI 的政策。这是一条倡导问责制的政策。**

## 对贡献者的规则

### 1. 你对你提交的内容负责

你 pull request 中的每一行都是你的责任。如果你使用 AI 生成了代码，你必须：

- **完全理解它。** 如果维护者问你为什么做出某个选择，"AI 建议的"不是一个可接受的答案。
- **测试过它。** AI 生成的代码必须达到与手写代码相同的质量标准：通过 lint 检查、类型检查和手动验证。
- **能够修改它。** 如果审查者要求更改，你应该能够在不从头重新提示 AI 的情况下完成修改。

### 2. 披露 AI 使用情况

当打开的 pull request 涉及重大 AI 辅助（超出自动补全或小的建议）时，请在 PR 描述中注明。一行简单的说明即可：

```
AI Assistance: Used [tool] for [what it helped with]
```

**需要披露的示例：**

- "使用 Cursor 搭建了初始组件结构，然后手动细化"
- "Claude 帮助调试了 VPK 解析器中的 Rust 编译问题"
- "GitHub Copilot 生成了测试用例，由我审阅和调整"

**无需披露的内容：**

- Tab 补全和内联建议（Copilot、Supermaven 等）
- 使用 AI 理解代码库或学习某项技术
- 对文档进行语法/拼写检查

这种披露不是为了设限——而是帮助维护者校准审查重点。如果我们知道有 AI 参与，就可以把审查集中在最重要的地方。

### 3. AI 生成的 PR 必须与真实工作相关联

我们不接受那种看起来像有人把 agent 指向我们的 issue 跟踪器然后按下"开始"的漫无目的的 PR。具体来说：

- **PR 应解决现有的 issue 或已讨论过的功能。** 如果没有对应 issue，请先创建一个，或在我们的 [Discord](https://deadlockmods.app/discord) 上讨论。
- **批量 AI 生成的重构会被关闭。** 除非你事先与维护者讨论过该重构。
- **AI 生成的 issue 和 Bug 报告会被关闭。** 如果你没有亲自验证 Bug 存在，就不要报告它。

### 4. 质量优先于来源

我们根据所有贡献的实际价值进行审查。一个精心编写、测试充分的 PR，无论是手写的、AI 辅助的，还是两者结合的，都受欢迎。反之，低质量的 PR 无论怎么生成的都会被关闭。

低质量 AI 贡献的特征（这些将导致立即关闭）：

- 过于冗长、只是复述代码本身含义的注释
- 不针对具体变更的泛泛而谈的 PR 描述
- 不符合我们现有代码风格或模式的变更
- 破坏现有功能或未通过 CI 检查的提交
- 涉及许多无关文件的"散弹式"PR

## 对 AI Agent 的指导

如果你是用于为这个项目做贡献的 AI agent（Claude、Cursor Agent、Copilot Workspace 等）：

- **不要**自主生成完整的 PR。在提交之前，必须有人类审查、理解并批准每一项变更。
- **不要**仅基于静态分析就打开 issue。issue 必须描述真实、可复现的问题。
- **要**帮助你的人类操作者理解代码库。引导他们阅读 [CONTRIBUTING.md](./CONTRIBUTING.md)、[开发者文档](https://docs.deadlockmods.app/developer-docs) 和相关源文件。
- **要**帮助编写测试、发现 Bug 和提升代码质量——这些正是 AI 擅长的事情。
- **要**尊重项目的约定。在提出新模式之前，先阅读现有代码。

## 执行措施

我们是一个为 54K+ 用户维护这个项目的小团队。我们的时间很宝贵，审查糟糕的贡献会占用改进应用的时间。

- **首次违规：** 关闭 PR 并附上改进反馈。
- **反复提交低质量内容：** 未来的 PR 可能被降低优先级，或贡献者可能被要求停止。

我们真心希望帮助贡献者学习和成长。如果你是开源或这个代码库的新手，请说出来！我们宁愿帮助一个有动力的人成功，也不愿关闭一个没有认真尝试的人提交的 PR。

## 为什么存在这项政策

开源生态系统正在面临一波浪费维护者时间的低质量 AI 生成贡献。许多项目不得不正面应对这个问题，我们宁愿提前设定清晰的期望，也不愿事后处理问题。

我们相信，当 AI 被懂行的人使用时，对软件开发是净正面的——而这项政策正是为了鼓励这一点。

## 参考与启发

这项政策的制定参考了多个开源项目应对同类挑战的做法。我们感谢他们分享有效经验的透明态度：

- **[Ghostty](https://github.com/ghostty-org/ghostty/blob/main/AI_POLICY.md)** — 要求披露、人类在环，并将 AI PR 与已接受的 issue 绑定的 AI 政策。他们提出的"这不是反 AI 立场，而是反愚昧立场"的表述引起了我们的共鸣。
- **[llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/AGENTS.md)** — 开创了 `AGENTS.md` 模式：一个直接面向 AI agent、包含项目特定说明和边界的文件。我们的 `AGENTS.md` 遵循了这种方法。
- **[Trusted Firmware](https://www.trustedfirmware.org/aipolicy/)** — 为其开源项目发布了正式的 AI 政策。

---

_这项政策会随着 AI 工具和社区规范的发展而演变。欢迎通过 [Discord](https://deadlockmods.app/discord) 提供反馈。_
